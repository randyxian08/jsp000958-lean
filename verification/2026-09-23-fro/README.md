The submitter ran these checks; they are not organizer verification, an independent third-party review, a priority decision, or an award.

The comparator invoked Landrun, built the [Challenge](Challenge.lean.txt) and [Solution](Solution.lean.txt) modules, compared the selected theorem statement, restricted axioms to `propext`, `Quot.sound`, and `Classical.choice` in [comparator.json](comparator.json), and replayed the solution in Lean's default kernel. The [raw log](comparator.log.gz) ends with `Lean default kernel accepts the solution` and `Your solution is okay!`; its SHA-256 is `c5e0e11699c729e2abacdd698a83cabaa9129eb4fa0de77ff4b93357139b59a8`. The submitter-controlled challenge is not a challenge furnished by the organizers. Outer `systemd-run` was not available in the container; the container had no host credential mounts and its network was disconnected. Any further acceptance, priority, and identity checks remain with the organizers.

To reproduce, use a disposable checkout of proof commit `d85351c2c0b9c6357741e8fa2c2a3d9747b49919`. Copy `Challenge.lean.txt` and `Solution.lean.txt` from this evidence directory to the project root as `Challenge.lean` and `Solution.lean`, alongside `comparator.json`, then append two Lake library stanzas to the checkout's `lakefile.toml`: `[[lean_lib]]` with `name = "Challenge"` and `[[lean_lib]]` with `name = "Solution"`. Prepare the pinned Mathlib cache, build the comparator at `3927ad383f208ae977c340a91c48ac9b497d2097` and its locked `lean4export` dependency, and build Landrun from `811cfff51ceaf3d9843708aa6d22e9b84ccac8b4`. In an unprivileged network-disabled Linux environment, set `COMPARATOR_LANDRUN` and `COMPARATOR_LEAN4EXPORT` to those binaries, then run `lake env /path/to/comparator comparator.json` from the disposable checkout. This harness change is not part of proof commit `d85351c2c0b9c6357741e8fa2c2a3d9747b49919`.

For the external-kernel run, build `nanoda_bin` from source commit `3a2407216ee84a75f9e1aead6803d0578be06ae7`, set `COMPARATOR_NANODA` to its path, and run the same comparator command with `comparator.nanoda.json`. The configuration changes only `enable_nanoda` to `true`.

The `.log.gz` files decompress to the original stdout/stderr logs; their uncompressed and compressed SHA-256 hashes are in `summary.json`.
